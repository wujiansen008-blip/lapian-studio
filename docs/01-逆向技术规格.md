# 千川爆款拉片工具 · 逆向技术规格

> 目标：复刻一个功能等价的自研版本，用于自有内容生产流程。
> 来源：对 `千川爆款拉片工具-0.1.17-hotfix.18-Setup.exe` 的静态分析。
> 边界：**只复用业务逻辑与方法论，代码全部重写**；不沿用其品牌、图标、UI 外观、激活与计费体系。

## 2. 完整数据流

```
用户上传视频文件
   │
   ├─[浏览器] <video> 读取元数据（duration / videoWidth）
   │
   ├─[浏览器] 抽 N 帧 ────────────────→ state.frames(时间区间 + JPEG base64)
   │     │
   │     ├→ 裁剪下半区 → Tesseract OCR(chi_sim+eng) → 分镜字幕文本
   │     └→ 拼「分镜联系表」canvas → S1..Sn 分格图（JPEG base64）
   │
   ├─[HTTP] POST /api/transcribe  视频原始字节
   │     └─[Node] 写临时文件 → 调 whisper-cli → 输出 JSON → 规范化 segments
   │            → { segments:[{start,end,text}], text }
   │
   └─[浏览器] buildAnalysis() 本地规则引擎（纯关键词/规则，不调 AI）
          → localAnalysis { layer, perspective, audience, opening, selling, ... }

──────────── 以上全部本地完成，零成本 ────────────

[HTTP] POST /api/ai/analyze
  payload = { transcript, productInput, audienceInput, localAnalysis,
              frames[], contactSheets[] }
  → [云端] OpenAI Responses API，model=gpt-5.5，max_output_tokens=4200
     输入 = systemPrompt + 素材 JSON + 联系表图片(input_image, detail=high)
  → 严格 JSON → normalizeCloudAnalysis() → 渲染详情 / 分镜表
```

**双阶段设计**：先在本地跑规则引擎得到"毛坯结论"，再把结论 + 转写 + 联系表交给 AI 精修。这样即使 AI 不可用，用户也有可用产出，同时显著降低 token 消耗。

## 3. 关键工艺参数

### 3.1 抽帧（前端 Canvas，不需要 ffmpeg）

```js
count   = 用户可调，默认 9（shotCountInput）
canvas.w = 540；canvas.h = 540 / (videoW/videoH)
对每一帧 i：
  start = duration / count * i
  end   = duration / count * (i+1)
  time  = i === 0 ? min(0.4, duration/3) : min(start + 0.45, duration - 0.1)
  先填 #111827 底色，再 drawImage，输出 toDataURL('image/jpeg', 0.84)
```

要点：
- 用等分区间 + 区间起点后 0.45s 取帧，避开转场黑帧
- 首帧特殊处理（0.4s），避免片头黑屏
- 竖版比例自适应

### 3.2 字幕 OCR（前端）

- 裁出画面下半部分：`cropY = h * 0.52`，裁到画面底部
- 引擎：Tesseract.js，语言包 `chi_sim+eng`
- 用途：当音频转写不可用/不准时，作为第三条证据来源
- 证据优先级：`audio > ocr > manual`

### 3.3 分镜联系表（前端 Canvas 拼图）

单视频：
```
每张最多 9 格，3 列布局
cellWidth = 300, imageHeight = 500, labelHeight = 44
底 #f3f6fa，格内 #111827 补边、等比居中
格下方白条 + #dbe5f2 描边 + 标签：
  "S{index+1}  {mm:ss}-{mm:ss}"，字体 700 16px
输出 toDataURL('image/jpeg', 0.78)
frameIndexes → 记录每格对应哪一帧
```

终局对比（左右配对表）：
```
cellWidth = 340, imageHeight = 430, rowLabelHeight = 42, headerHeight = 48
两列表头：BENCHMARK / 对标视频 | FINAL / 成品视频
每行：Bn 时间区间 | Fn 时间区间
一张图搞定整条对比，避免多图请求
```

**为什么要拼图**：把 9 张图压成 1 张，云端图片请求数降一个数量级，同时让模型获得同一张图内的顺序上下文。

### 3.4 本地 Whisper 转写（Node 侧）

```
whisper-cli.exe
  -m  models/ggml-small.bin
  -f  <临时文件>            （直接把视频字节写盘，whisper 自带解码）
  -l  <auto→zh 等>
  -oj -of <输出前缀>        （JSON + TXT 双输出）
  -t  clamp(cpu核数, 2, 8)
  --prompt "<领域词表提示>"   （关键：喂产品名/品牌/行业术语，显著提升专名准确率）
cwd = whisper 根目录；PATH 前置 bin 目录（解决 dll 依赖）
超时 15 分钟
```

**转写提示词构造**（原作者的做法，值得保留）：
```
"请优先按普通话短视频口播转写，不要翻译。
 品牌/产品名：{product}。
 目标人群/场景：{audience}。
 常见带货术语：益生菌、空腹、早B晚S、B420、S600……"
截断到 420 字
```
→ 复刻时改为**用户可维护的行业词表**，按品类自动注入。

### 3.5 本地规则引擎（前端，零成本预热分析）

`buildAnalysis()` 是纯规则实现，输入「转写文本 + 产品词 + 人群词 + 文件名」，输出结构化初判：

| 字段 | 判定方式 |
|---|---|
| layer | 3.1 用户视角/场景痛点/品类价值｜3.2 产品证明/成分功能/选择理由｜3.99 价格权益/强转化 |
| perspective | 用户视角 / 产品视角 / 价格视角 |
| audience | 人群关键词命中 |
| opening | 21 式黄金 3 秒之一（按首句特征词） |
| selling | 卖点顺序 |
| scene / signal | 场景与信号词 |
| middleMode | 五感种草归类（含"嗅觉与味觉"特例） |
| ending | 按 layer 推导（3.99→饥饿营销，3.2→背书引导，其余→痛点引导） |

→ 复刻时保留这个思路，但规则表做成**可配置 JSON**，方便你按品类调。

## 4. AI 层

### 4.1 调用协议

- 协议：OpenAI **Responses API** 格式（`/v1/responses`）
- 请求体：`{ model, input: [{ role:"user", content:[{type:"input_text"},{type:"input_image", image_url, detail}] }], max_output_tokens }`
- 图片以 **base64 data URL** 直接内联
- 输出解析：`parseModelJson()` → 剥 Markdown 代码块 → JSON.parse，失败重试提取首个 `{...}`

> **复刻改动**：改用标准 OpenAI Chat Completions（`/v1/chat/completions`）+ `image_url` 多模态消息，兼容 DeepSeek / 豆包 / 通义 / 智谱 / 硅基流动等所有 OpenAI 兼容服务。Responses API 目前仅 OpenAI 原生支持，兼容性差。

### 4.2 任务一：爆款拉片分析（完整提示词）

`max_output_tokens: 4200`，验证码级全文见 `prompts/analyze.md`。核心方法论：

1. **爆量三段论**：开头抓眼球 / 中段强种草 / 结尾促转化
2. **21 式黄金 3 秒**：点名受众、警告避坑、福利优惠、名人背书、用户口碑、揭露痛点、彰显效果、提出疑问、内幕揭秘、数据支撑、反差对比、反常识、情绪共鸣、猎奇好奇、直陈结论、炫耀成就、夸张句式、正话反说、时事热点、指令动作、名言金句
3. **内容三层分类**（整条素材只给一个）：3.1 用户视角/场景痛点/品类价值；3.2 产品证明/成分功能/选择理由；3.99 价格权益/强转化
4. **中段五种种草**：视觉、听觉、触觉联想、嗅觉与味觉、情感、认知
5. **六线脚本法**（固定六项）：本线（客观事件线）、主线（中心推进线）、支线（辅助叙事）、BGM 线、支线二（复刻执行线）、情绪曲线
6. **26 种情绪标签**：期待、好奇、惊喜、兴奋、喜悦、信任、安心、专注、平静、认同、同情、感动、心疼、紧张、担忧、恐惧、震惊、疑惑、压抑、沮丧、悲伤、愤怒、厌恶、反感、爽感、释然
7. **分镜逐格核对**：联系表每格必须独立识别，Sn 对应 `frameTimes[n-1]`，不允许把整表当一个镜头
8. **禁止泛泛描述**：画面描述必须以分镜图为准，口播只作语义参考

### 4.3 任务二：投放复盘（`max_output_tokens: 2600`）

输入：**四张千川后台截图**（投放数据总览、整体点赞、整体流失、整体点击）+ 拉片结论 + 分镜时间线。
输出：`{ summary, verdict(继续投放/优化后再投/建议停投), screenshotFindings[4项], recommendations[] }`
硬约束：看不清必须写"证据不足"，**禁止编造数值**。

### 4.4 任务三：终局对比（`max_output_tokens: 3200`，带视觉降级）

输入：对标视频分镜 + 成品视频分镜（左右配对联系表）+ 双方转写 + 分镜对。
输出：总评分 + 逐分镜对比 + **13 项固定维度**打分 + 修改建议。
视觉失败自动降级为纯文本对比（并明确标注证据不足）。

13 项维度：视频目标定位、数据提取.视频时长、视频时长标签、脚本文案、开头分析+黄金3秒提取、开头分析标签、卖点分析与可视化、卖点可视化分析、脚本结构与节奏分析、分镜头分析表、节奏与风格分析、结尾分析、结尾分析标签。

## 6. 复刻技术选型（本项目）

| 层 | 原版 | 本项目 | 理由 |
|---|---|---|---|
| 外壳 | Electron | **Electron 33** | 必须本地起 Node、跑 whisper 子进程、读本地视频 |
| 渲染层 | 353KB 原生 JS 单文件 | **Vue 3 + Vite** | 原版无模块化，改一处崩一片，不可维护 |
| 本地服务 | server.mjs 132KB 单文件 | **按功能拆分模块**（transcribe / analyze / ocr-bridge / settings） | 可测试、可扩展 |
| 语音转写 | whisper.cpp + ggml-small（内置） | **whisper.cpp 官方 Release + 模型按需下载** | 模型 487MB 不该进安装包，改为首启下载 |
| 字幕 OCR | Tesseract.js (chi_sim+eng) | 同（Tesseract.js） | 纯前端，无额外依赖 |
| 抽帧/拼图 | 前端 Canvas | 同思路，参数可调 | 已验证有效，无需 ffmpeg |
| AI 接入 | 作者代理 gpt-5.5 | **OpenAI 兼容多供应商直连**，用户填 Key | 去掉中间层，成本可控、模型可换 |
| 激活/计费 | Ed25519 + 机器码 + 微信支付 | **全部移除** | 自用无需 |
| 更新 | GitHub 私有仓库 | 本地打包分发 | 不需要 |

### 首启模型下载方案
`ggml-small.bin` 487MB 从 HuggingFace 拉取，可选 `base`(142MB) / `small`(487MB) / `medium`(1.5GB)，按机器性能与精度需求选择。首次启动引导下载并校验 SHA256。

## 7. 与原版的有意差异

1. **去掉全部授权与计费**：无激活码、无算力积分、无支付。
2. **AI 直连**：不经过任何第三方中转，Key 存本地加密配置。
3. **词表可配置**：转写提示词的产品/品牌/行业术语做成可视化编辑，按品类切换。
4. **模型可选**：转写模型、分析模型都可换。
5. **界面重画**：保留"导入 → 分析中 → 报告"的信息架构，视觉重做。
6. **保留飞书多维表格写入能力**（原版 `/api/feishu/*` 的同等能力），对接自有素材管理表。
