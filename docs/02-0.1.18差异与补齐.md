## 三、本次已补齐

### 1. 四套提示词全部对齐 0.1.18
`server/prompts-core.mjs` 由脚本从 0.1.18 的 server.mjs 直接切出，未手工改写措辞。

### 2. 拉片报告新增字段展示
- 顶层四问：卖什么 / 卖给谁 / 为什么吸引 / 为什么转化
- `reviewEditIdea`：剪映逐帧剪辑脚本（画面轨 / 字幕轨 / 音效轨 / Tips）
- 每个分镜的复刻六件套：原片作用、可复用结构、替换为、新口播、拍摄指令、不可照抄
- `visualDescription` 升级为 160–260 字的视频生成提示词

### 3. 逐镜裂变（新增第 4 个模式）
- 11 种槽位角色 × 4 种策略（槽位裂变 / 素材补充 / 保留原版 / 证据待补）
- 每个槽位输出：口播池（3 条）、画面池（3–5 条）、字幕池（2–3 条）、组合规则、验证指标
- 输出 token 上限 16000，超时 7 分钟

### 4. 投放复盘 / 终局对比提示词升级
后端已换用 0.1.18 完整版（含 curvePeak 与 timelineAlignment）。

### 5. 分镜视频导出（内置 ffmpeg）
- 上传视频时按 SHA256 缓存到 `%APPDATA%\lapian-studio\media-cache\sources\`
- `POST /api/media/source` 注册源视频（上限 2GB，重复上传自动复用）
- `POST /api/media/export` 按分镜区间批量切片到用户选定目录（系统目录选择框）
- 参数与 0.1.18 一致：`libx264 / veryfast / crf 20 / yuv420p / aac 160k / +faststart`
- 文件名：`S01_00m00s000-00m03s000.mp4`
- 实测：3 段切片全部成功，ffmpeg 校验为 h264 High + aac，时长精确（3.02s）

### 6. 三段式抽帧
- 每个分镜取 **10% / 50% / 90%** 三个时间点作为视觉证据
- 联系表按「一镜三格」重排：每张 3 镜 × 3 相 = 9 格，标注 `S1-前 / S1-中 / S1-后`
- 9 镜实测生成 3 张联系表（3x3 / 3x3 / 3x3），全部发给模型
- 分镜列表与导出仍以中间帧为主图，下游语义不变

### 7. 耗时计时
状态栏实时显示已用秒数，避免长任务（裂变 2-4 分钟）被误认为卡死。

### 8. 历史记录
- 每次 AI 拉片成功后自动存档，关掉应用不丢结果
- 存储：`%APPDATA%\lapian-studio\history\{id}\record.json` + 分镜图独立 jpg（不塞进 JSON）
- 接口：`GET/POST /api/history`、`GET /api/history/:id`、`GET /api/history/:id/img/:file`、`DELETE /api/history/:id`
- 列表显示缩略图 / 时长 / 帧数 / 时间 / 三层标签；点「载入」自动切回拉片模式并恢复报告
- 自动裁剪：超过 200 条删除最旧
- 实测：保存 → 列表 → 详情（图片 URL 化）→ 图片流 200 → 删除 → 列表清空，全链路通过

### 9. 脚本总结 14 项 + 画面总结 4 维（对齐实机版式）
实机渲染原版后确认其报告结构，已按此重做：

### 10. 报告图片导出（html2canvas，2x PNG）
- 顶栏「导出图片」按当前模式导出对应报告：图1-框架拆解 / 图2-爆款复盘 / 图3-成品分析 / 图4-爆款迭化

### 11. 图2 分镜拉片（补上第 6 个页面）
原版 6 个页面里唯一缺失的一个，已按实机结构实现：

## 五、ffmpeg 切片参数（备查）

```
-hide_banner -loglevel error -y
-i <源视频>
-ss <start> -t <duration>
-map 0:v:0 -map 0:a?
-c:v libx264 -preset veryfast -crf 20 -pix_fmt yuv420p
-c:a aac -b:a 160k
-movflags +faststart
```
源视频按 SHA256 命名缓存（上限 2GB），切片按 `sha256(source|start|end|h264-aac-v1)` 缓存。
